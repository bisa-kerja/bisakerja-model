# Bisakerja Model Workspace

Model, inference, evidence, and Model API workspace for the Bisakerja AI career platform.

This repository is focused on the model side only: notebook-first model training, production Model API serving, release evidence, validation scripts, tests, artifacts, reports, and a frozen legacy snapshot. The Backend API is a separate repository: <https://github.com/bisa-kerja/bisakerja-api>.

## Platform Context

Bisakerja helps Indonesian job seekers understand job fit, improve CV quality, and choose relevant applications. The broader platform has these boundaries:

| Workspace                    | Responsibility                                                                                                                                                        |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backend API                  | External repo at <https://github.com/bisa-kerja/bisakerja-api>. Owns auth, users, jobs, persistence, public REST API, wrapper copy, hydration, and product workflows. |
| Model Training (`training/`) | Notebook-first training, feature design, evaluation, calibration, model export, and release evidence.                                                                 |
| Model API (`model_api/`)     | Internal FastAPI serving package for model-core inference over exported artifacts.                                                                                    |
| Artifacts (`artifacts/`)     | Durable model, validation, fixture, TensorBoard, and release-gate outputs.                                                                                            |
| Reports (`reports/`)         | Human-readable and machine-readable evidence generated by notebooks and verification scripts.                                                                         |
| Legacy (`legacy/`)           | Historical snapshot kept for audit and comparison only.                                                                                                               |

Frontend clients must call Backend API. They must never call Model API directly.

## Service Boundary

Model workspace owns model-core output only:

- `jobFitAlignment`
- `atsFriendliness`
- `overallImpression`
- `candidateReranking` scores for Backend-provided candidates

Backend owns product and persistence concerns:

- authentication and authorization
- CV ownership and upload validation
- database reads/writes
- final `CvAnalysis` response shape
- `topActionables`, `sectionReviews`, generated prose, and hydrated job recommendations
- GenAI wrapper orchestration and fallbacks

Backend contract alignment should use exported contracts or fixtures from <https://github.com/bisa-kerja/bisakerja-api>. Do not treat Backend source as part of this model repository.

## Quick Start

Copy the Model API env template:

```bash
cp model_api/.env.example model_api/.env
```

Root `.env.example` is optional. It only contains model-workspace orchestration defaults and the external Backend repo URL.

Install Model API runtime dependencies with Python `3.13.11`, the same version used by the TensorFlow notebook runtime:

```bash
PYENV_VERSION=3.13.11 pyenv exec python -m venv .venv
source .venv/bin/activate
python -V
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If you do not use `pyenv`, make sure `python -V` prints `3.13.11` before creating `.venv`. Do not use Python `3.14` for TensorFlow/Model API smoke checks.

Run Model API locally:

```bash
export MODEL_API_ENV=local
export MODEL_API_SERVICE_TOKEN=replace-with-local-service-token
uvicorn model_api.app:create_app --factory --host 0.0.0.0 --port 8000
```

Check readiness:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:8000/ready
curl -H "authorization: Bearer ${MODEL_API_SERVICE_TOKEN}" http://127.0.0.1:8000/model-info
```

Run targeted tests:

```bash
python -m unittest tests.model_api.test_phase_26_layout
python -m unittest tests.test_phase_29_model_api_hardening
python -m unittest tests.test_phase_31_release_gate
```

## Training Runtime

Training is notebook-first. Do not add training package entrypoints under `training/*.py` unless the workflow is intentionally changed.

Use Python `3.13.11` for TensorFlow training and release evidence:

```bash
PYENV_VERSION=3.13.11 pyenv exec python -m venv training/.tf-venv-3.13
source training/.tf-venv-3.13/bin/activate
python -V
python -m pip install --upgrade pip
python -m pip install -r training/requirements.txt
```

Main production notebook:

```text
training/notebooks/phase_25_tensorflow_training_delivery.ipynb
```

## Release Gates

Production-ready claims require clean release evidence, not only local notebook output:

```bash
python scripts/verify_phase_27_1_27_2_release_gate.py --write
python scripts/verify_phase_27_3_27_4_release_evidence.py --write
python scripts/verify_phase_27_5_27_6_validation_expansion.py --write
python scripts/verify_phase_27_9_model_api_production_smoke.py --write --run-live
python scripts/verify_phase_31_release_gate.py
python scripts/verify_phase_36_ai_cv_analyzer_staging_gate.py
```

Some gates require TensorFlow, E5, generated artifacts, external Backend contract fixtures, or live local services.

## Safety Rules

- Keep this repo model-focused.
- Keep Backend source in <https://github.com/bisa-kerja/bisakerja-api>, not inside this repo.
- Keep Model API stateless and without DB credentials.
- Do not commit real `.env` files, service tokens, DB URLs, raw CV text, or unrelated PII.
- Do not mutate model artifacts at runtime.
- Update README/docs together with behavior, contract, environment, or operational changes.
